# commsgun (email/SMS hub)

Tailnet services POST a message to `commsgun`; it queues it durably, sends email through Resend within the app and
provider limits, tracks bounces and shows the outcome on a dashboard. SMS is accepted and held: no provider exists yet.
Two containers on the edge, behind Caddy on two tailnet-only names (`*.ts.<domain>`, no ACME work needed):

| Name | Container | Host port | Use |
|---|---|---|---|
| `comms.ts.<domain>` (`commsgun_enqueue_hostname`) | `commsgun-api` | `127.0.0.1:9200` | apps POST `/v1/messages`; Gatus probes `/healthz`, `/healthz/backlog` |
| `commsgun.ts.<domain>` (`commsgun_ui_hostname`) | `commsgun-ui` | `127.0.0.1:9202` | read-only dashboard; `/healthz` for Gatus |

The admin port 9201 is never published. The service's own docs: `README.md` and `docs/superpowers/specs/` in
`davcs86/commsgun`. Traps: `docs/decisions.md` § Known traps. Secret shapes: `secrets/README.md`.

Commands below run from the repository root; `sops` needs `SOPS_AGE_SSH_PRIVATE_KEY_FILE=~/keys/sops_admin` (as in
`secrets/README.md` § Read a value locally).

## 1. First deploy

Outside Ansible, by hand, before the deploy:

1. **Resend sender domain.** In Resend, add the domain you will send from and add the DKIM and SPF records it shows at
   the domain's DNS host. Wait until Resend shows the domain as verified.
2. **Resend API key with full access.** Bounce tracking reads email status, which a sending-only key cannot do: with one,
   every status poll fails. Resend shows the key once; keep a copy.

Then in this repository:

3. **Secrets.** `secrets/edge.sops.yaml` must hold all of these (shapes in `secrets/README.md`):
   - generated by **Actions → init-secrets** with `fill_missing`: `commsgun_admin_password`, `commsgun_session_secret`,
     `commsgun_admin_api_token`, `commsgun_app_key_xstockstrat`, `commsgun_app_key_ops`, and
     `commsgun_app_key_xstockstrat_staging` (the staging app's key);
   - added by you with `sops set` (`fill_missing` keeps them, `overwrite` deletes them): `resend_api_key` and
     `commsgun_senders` (a map from app id to `senders` and `default_sender`; an entry for **each** of `xstockstrat`,
     `xstockstrat-staging` and `ops`, the apps in `commsgun_apps`). Use addresses on the verified domain.

   ```sh
   sops set secrets/edge.sops.yaml '["resend_api_key"]' '"<full-access Resend key>"'
   sops set secrets/edge.sops.yaml '["commsgun_senders"]' '{"xstockstrat": {"senders": ["Alerts <alerts@example.com>"], "default_sender": "Alerts <alerts@example.com>"}, "xstockstrat-staging": {"senders": ["Alerts <alerts@example.com>"], "default_sender": "Alerts <alerts@example.com>"}, "ops": {"senders": ["Ops <ops@example.com>"], "default_sender": "Ops <ops@example.com>"}}'
   ```

   A secret value may not contain a quote, backslash or line break (the deploy refuses it; see `docs/decisions.md`).
   Commit both hand-added keys and get them merged to `main` before step 5; the deploy does not see a value that is
   only in your working copy or on an unmerged branch.
4. **Check the limits.** `commsgun_providers` and `commsgun_apps` in `inventories/prod/group_vars/all/main.yml` hold the
   provider limit (`resend`: 60 per minute, 100 per day) and each app's per-channel limits, confirmed by the owner on
   2026-11-13. The apps' daily email limits sum to 105 on purpose: the provider cap wins and the excess is deferred.
5. **Deploy.** Run **Actions → deploy** (`tailnet`). Merging the PR that brought the code deployed nothing. If the
   deploy fails anywhere in the stack role (one of the commsgun checks below, or at or after "Start the stack"), follow
   `docs/runbooks/recovery.md` § "After a deploy that failed part-way" before re-running: earlier tasks of that run
   have already written files (the Gatus config among them) whose restarts the failure dropped.

   On the first deploy Gatus may alert once for the commsgun probes and then resolve: they start before the deploy
   writes the split-horizon records for the two names. Nothing in the deploy itself proves the new routes work; the proof
   is the three Gatus probes (`commsgun-api`, `commsgun-backlog`, `commsgun-ui`) green and the checks below.

Verify from a tailnet device that may reach the edge on 443 (your own devices, or `tag:xstockstrat`). Replace
`<domain>` and `<your address>`; the `ops` app key is read from SOPS. The `send` function takes two arguments: a suffix
for the idempotency key (`verify-<suffix>`) and the JSON body:

```sh
KEY=$(sops decrypt --extract '["commsgun_app_key_ops"]' secrets/edge.sops.yaml)
send() {
  curl -sS -i -X POST "https://comms.ts.<domain>/v1/messages" \
    -H 'X-Commsgun-App: ops' -H "Authorization: Bearer $KEY" \
    -H "Idempotency-Key: verify-$1" -H 'Content-Type: application/json' -d "$2"
}
send 1 '{"channel":"email","to":["<your address>"],"subject":"commsgun check","text":"hello"}'
```

The enqueue contract: headers `X-Commsgun-App`, `Authorization: Bearer <that app's key>`, `Idempotency-Key` (1 to 200
characters of `A-Za-z0-9._:-`), JSON body. Email: `channel`, `to` (1 to 10 addresses, one message each), `subject`, `text`
and/or `html`, optional `from` (must be an allowed sender of the app; the default sender is used when absent),
`reply_to`, `expires_at`. SMS: `channel`, `to` (E.164), `body`. Replies: 202 queued (`request_id`, `message_ids`), 200 same
key and body again (`"duplicate":true`), 401 unknown app or wrong key, 403 channel not enabled, 409 key reused with a
different body, 413 over 256 KiB, 422 invalid body or sender, 429 over the app's limit (`Retry-After`), 503 busy
(retry with the same key).

Log in to the dashboard at `https://commsgun.ts.<domain>/login`: user `admin`, password from
`sops decrypt --extract '["commsgun_admin_password"]' secrets/edge.sops.yaml`. Then check each of these:

- **Delivered.** The send above returns `202`. The dashboard (default range 1h) shows it as Sent, then `delivered`
  within a few minutes (status is polled at 1 min, 5 min, 30 min, 2 h, ...).
- **Bounced.** `send 2 '{"channel":"email","to":["bounced@resend.dev"],"subject":"commsgun bounce","text":"hello"}'`
  reaches `bounced` on the dashboard (filter state `bounced`).
- **SMS held.** `send 3 '{"channel":"sms","to":["+15551234567"],"body":"hold"}'` returns 202; the Overview shows
  "No provider · 1 held" for SMS and the message detail says "Held: no SMS provider configured". Nothing is sent.
- **Day limit.** `ops` may send 5 emails per UTC day and 2 per minute; the two above already count. Send three more
  (`send 4`, `send 5`, `send 6`, same email body to your address, no more than two in the same minute), then
  `send 7` returns `429` with a `Retry-After` header and `{"error":"rate_limited","window":"day"}`. A `"window":"minute"`
  answer means wait a minute; it does not prove the day limit.
- **Unreachable from outside.** From a device off the tailnet (phone on mobile data, tailscale off):
  `curl -sS --max-time 10 -o /dev/null -w '%{http_code}\n' https://comms.ts.<domain>/healthz` and the same for
  `https://commsgun.ts.<domain>/healthz` print `000` or fail to resolve; neither may return an HTTP status.
- **Gatus.** `https://status.ts.<domain>`, group `edge`: `commsgun-api`, `commsgun-backlog` and `commsgun-ui` are green.
- **Unauthenticated.** `curl -s -o /dev/null -w '%{http_code}\n' -X POST https://comms.ts.<domain>/v1/messages -d '{}'`
  (from the tailnet) prints `401`.

## 2. Add a subscriber app

1. `inventories/prod/group_vars/all/main.yml`, `commsgun_apps`: add an entry with `id`, `key: commsgun_app_key_<app>`
   (an app id with `-` uses `_` in the key name: `xstockstrat-staging` -> `commsgun_app_key_xstockstrat_staging`) and
   `channels` with the `per_minute` and `per_day` of each channel the app may use. An app that may send email needs the
   `email` channel and a sender entry (step 4); a channel not listed returns 403.
2. `scripts/init_secrets.py`: add `commsgun_app_key_<app>` to the tuple of generated commsgun keys (`GENERATED`).
   Push steps 1 and 2 to a branch and open its PR; its CI is red until step 3 has run (the inventory names a key the SOPS
   file lacks).
3. **Actions → init-secrets → Run workflow**, choose **the PR's branch** (not `main`), tick `fill_missing` (never
   `overwrite`, which deletes the keys you added by hand). The workflow runs `scripts/init_secrets.py` from the branch it
   is run on and pushes its commit to that branch; run on `main`, it does not know the new key, prints "nothing to
   commit" and the PR stays red. The run needs approval on the `production` environment, which must allow the PR's
   branch: `docs/runbooks/github-push-token.md` step 1 restricts `production` to `main`, and with that restriction in
   place this step is blocked (lift it for the branch, or land steps 1–2 on `main` first and run the workflow there).
   Approving it runs the branch's own `scripts/init_secrets.py` and workflow file with the push token and the SOPS key,
   so read the PR's changes to those two files first.
4. Pull that commit, then add the app's senders (keep the existing entries; `sops set` on the whole map replaces it, so
   use the app's own path), commit and push to the same branch:

   ```sh
   git pull
   sops set secrets/edge.sops.yaml '["commsgun_senders"]["<app id>"]' '{"senders": ["App <app@example.com>"], "default_sender": "App <app@example.com>"}'
   git add secrets/edge.sops.yaml && git commit -m "commsgun: senders for <app id>" && git push
   ```
5. Wait for CI on the PR to be green (CI does not check senders; the deploy does). Merge the PR, then run
   **Actions → deploy** (`tailnet`).
6. Hand the subscriber its app id, the key (`sops decrypt --extract '["commsgun_app_key_<app>"]' secrets/edge.sops.yaml`)
   and `https://comms.ts.<domain>/v1/messages`. Its tag needs a grant to `tag:edge:443`, as for `tag:xstockstrat`
   (`docs/runbooks/onboard-service.md`).

A step missed fails early, not at runtime: CI (`scripts/secrets-keys-test.py`) fails when the inventory names a key the
SOPS file lacks, and the deploy stops, before it writes any commsgun file, at "Commsgun secrets are present and fit a
single-quoted env line" (key missing, empty or holding a quote, backslash or line break), "Commsgun secrets are as long as
the service requires" (an app key, the session secret or the API token under 32 characters, the password under 16),
"Commsgun senders are a map", "commsgun_senders has no usable entry for app <id>" (no entry, `senders` empty or not a
list, a sender or `default_sender` not shaped `address` or `Name <address>`, or `default_sender` not one of `senders`), or
"commsgun_senders has <n> entries whose key is not the id of an app with an email channel". Check: send one email as
the new app (the `send` function above with its id and key) and see `202`, then the message on the dashboard
filtered by that app.

## 3. Rotate an app key or the admin password

1. Replace the value in SOPS. A key or password needs at least 32 (key, session secret, API token) or 16 (dashboard
   password) characters and no quote, backslash or line break:

   ```sh
   sops set secrets/edge.sops.yaml '["commsgun_app_key_ops"]' "\"$(python3 -c 'import secrets; print(secrets.token_urlsafe(36))')\""
   ```

   The same works for `commsgun_admin_password`, `commsgun_session_secret` and `commsgun_admin_api_token`.
2. Commit, merge, run **Actions → deploy** (`tailnet`). The deploy rewrites the env files and recreates the containers
   whose environment changed; queued messages survive (the `commsgun-data` volume is kept).
3. The old app key stops working at once (one key per app, no overlap): hand the subscriber the new one in the same
   window. Changing `commsgun_admin_password` or `commsgun_session_secret` signs every dashboard session out; log in again.

Check: the old key now gets `401`, the new one `202`; for the dashboard, the old password is refused at `/login` and the new
one works.

## 4. Change a limit

1. Edit `commsgun_apps[].channels.<channel>.per_minute` / `per_day` (an app's limit) or `commsgun_providers` (the
   provider's own limit) in `inventories/prod/group_vars/all/main.yml`.
2. Merge, run **Actions → deploy** (`tailnet`).

An app over its limit gets `429` with `Retry-After`, and the whole request is rejected (rate limits count messages, one per
recipient; fixed windows, the UTC minute and the UTC day). A provider limit delays instead: messages wait in the queue
until the window turns over and nothing is rejected. Check: the dashboard's provider usage bar shows the new daily
total; for an app limit, send past it and see `429`.

## 5. Configure an SMS provider

Not available yet. `commsgun_providers.sms` is `null`, so SMS is accepted (202) and held. A provider needs an
implementation in the `commsgun` repo first, then its pin bump (section 8) and the provider block here. Until then a held
message expires 24 hours after it was enqueued (never sent), so nothing old is sent the day a provider appears.

## 6. Read the dashboard

Tiles: **Sent** counts messages the provider accepted in the range; **Delivered**, **Bounced**, **Failed** and the other
outcomes are confirmed later (status polling after a send) and counted by when that happened, so the chart stacks only
those. **Queued** is waiting to be sent; **Retries** counts retried attempts.

The provider usage bar can show a pause:

| Wording | Meaning | Clears |
|---|---|---|
| Daily quota reached | the provider's `per_day` (or Resend's daily quota) is used | 00:00 UTC |
| Monthly quota reached | Resend's monthly quota is used | re-checked every 6 hours |
| Rate limited | the provider answered 429 | after its `Retry-After` |
| Provider rejected the API key | Resend refused `resend_api_key` | see below |

While paused, messages stay queued, no attempt is consumed, and each message still expires at its deadline (24 hours after
enqueue, 5 minutes less for the provider's idempotency memory). On "Provider rejected the API key" the hub pauses ten
minutes at a time and keeps the queue until messages reach their deadline: fix `resend_api_key` in SOPS
(`sops set ... '["resend_api_key"]' ...`), merge, run **Actions → deploy**. Remember the key must have full access.

**Held** means a message waits for a provider that is not configured (SMS today): "No provider · N held". A held message is
not an error and expires at its deadline. The Gatus probe `commsgun-backlog` goes red only when a message that could be
sent now has waited more than 15 minutes; held messages and quota pauses do not trigger it.

## 7. Remove or rename a provider or an app

Messages already queued for a removed or renamed provider (`commsgun_providers`), or for a removed app, stay queued. They
are not shown as held and they expire at their deadline (24 hours after enqueue); nothing is sent for them. A removed
app's key stops working at the deploy. Check: the dashboard's queued count falls to zero within 24 hours.

## 8. Image updates

The `bump-commsgun` workflow opens one PR (branch `bump/commsgun`) that pins both `commsgun_api_image` and
`commsgun_ui_image`: daily, or at once from **Actions → bump-commsgun → Run workflow** (optional digests to pin
instead of the newest). It proposes nothing when the two images' revision labels differ or are missing, so the API and
dashboard never ship from different commits. Merging deploys nothing: run **Actions → deploy** (`tailnet`) afterwards.
A docs- or CI-only merge in `commsgun` also produces a bump PR that changes nothing on the edge. Pin format and
rationale: `docs/versions.md`. Check: after the deploy, `ssh david_admin@edge 'sudo docker compose -f /opt/edge/compose.yml ps commsgun-api commsgun-ui'`
shows both running and the Gatus probes stay green.

## 9. Logs

The containers log message ids only (no addresses, subjects or bodies):

```sh
ssh david_admin@edge 'sudo docker compose -f /opt/edge/compose.yml logs --since 1h commsgun-api commsgun-ui'
```

The dashboard host has its own Caddy access log, `/var/log/caddy/commsgun-ui.access.log` on the edge, with query strings,
`Referer` and redirect `Location` removed (the dashboard's filters carry recipient addresses). The enqueue name logs to the
shared tailnet access log like the other `*.ts` names.
